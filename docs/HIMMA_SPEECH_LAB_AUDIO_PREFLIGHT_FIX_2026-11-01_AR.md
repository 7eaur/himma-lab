# إصلاح حاجز الصوت في مختبر هِمّة V2 — 2026-11-01

## السبب المؤكد

قبل التعديل، `lib/audio-quality.ts` صنف أي تسجيل بأقل من 550ms كـ `too_short`، وأي تسجيل `RMS < 0.0025` أو `Peak < 0.01` كـ `silence`. وكانت `blocksAnalysis` تمنع Azure من التحليل، وتحذف أي فرصة لاستقبال تصحيح بشري في المختبر.

حالة الواجهة الواقعية أظهرت `RMS = 0.0022` و`silenceRatio = 95%` ومنعت التحليل. **لا تدل هذه الأرقام وحدها على غياب النطق.** يوجد سجل سابق فيه `silenceRatio ≈ 98.6%` وتعرف Azure فيه على المرجع النصي كاملًا. 
`silenceRatio` هو نسبة إطارات الـ20ms التي تقل طاقتها عن ثابت `0.006 RMS` وليس معدل الصمت الحقيقي أو نتيجة VAD.

## الإصلاح

- لا يستخدم المختبر الشدة أو نسبة الإطارات منخفضة الشدة أو مدة الحرف لاتخاذ قرار بالرفض قبل Azure.
- `blocksAnalysis` يمنع WAV غير الصالح بنيويًا فقط. أما الصوت القصير أو المنخفض أو المحتوي على تأخر قبل النطق فيمكن تحليله، بما فيه الإشارة الرقمية الصفرية إذا اختار المستخدم إرساله كعينة تجربة.
- إشارة جميع الأصفار فقط تصنف `silence` كدليل تشخيصي لا كحكم قراءة، و`warning` تستخدم للبقية.
- تبقى قياسات الطاقة والمؤشرات في `audio_quality` وتبقى نتيجة التعرف في `asr_diagnostics` مع تسجيل أصل الصوت في Storage.
- النص الظاهر للطفل منفصل بصريًا عن ملاحظات المختبر، والواجهة لا تسمي القياس التقني «95% صمت» بل «إطارات منخفضة الشدة».
- لا يتم اعتماد نطق صحيح من هذا التعديل. عند عدم تعرف Azure على الكلام تبقى `retry_required` بدون أثر أكاديمي.
- الإصلاح محصور في فرع `experiment/simplified-speech-lab-20260921`. لا مساس بالمنصة الأساسية أو Production.

## حالات اختبار

`npm run test:audio-preflight` يختبر:
1. صوتًا ضعيفًا كانت عتبته تؤدي إلى رفض سابق.
2. حرفًا قصيرًا بعد تأخير طويل.
3. نطقًا مدته أقل من 550ms.
4. إشارة منخفضة جدًا ولكن ليست أصفارًا.
5. تسجيل جميع العينات فيه أصفار (يمكن إرساله تجريبيًا).
6. ملف WAV غير صالح (يبقى محظورًا).
7. ملف WAV بلا عينات (يبقى محظورًا).

بعد نشر Preview يجب تسجيل حالات واقعية للطفل والحصول على تقييم بشري ومقارنة نتائج Azure قبل اتخاذ قرار أكاديمي.
