# Himma Calibration Lab — Readiness

## الهدف

هذا المختبر مستقل عن منصة هِمّة الإنتاجية، ومهمته جمع بيانات نطق عربية موثوقة تساعد على معايرة محرك القراءة قبل السماح له بإصدار أحكام نطق آلية.

## ما يجمعه المختبر لكل عينة

- كود مشارك مجهول ينشئه المشرف فقط.
- مفتاح الهدف والنص المشكول ونوعه ومجموعته.
- ملف الصوت في Supabase Storage الخاص.
- نوع MIME والحجم والمدة التي سجلها المتصفح.
- مدة الصوت بعد فك الترميز، RMS، Peak، ونسبة الصمت عندما يدعم المتصفح ذلك.
- وسم المشارك: صحيح / خطأ / غير متأكد.
- النطق الذي يذكره المشارك عند الخطأ.
- جودة التسجيل التي يحددها المشارك وملاحظته الاختيارية.
- Azure locale/provider/transcript/confidence/duration/word timings/request id/error.
- النص المرجعي والنص الناتج بعد التطبيع.
- محاذاة Reference-Guided وتصنيفات Correct/Deletion/Insertion/Substitution.
- WER والدقة اللفظية.
- المرجع النطقي المشكول ووحدات النطق البشرية وأنواع الأخطاء المشتقة.
- حالة المعايرة وإصدار التحليل.
- حتى ثلاث مراجعات بشرية مستقلة مع observed text والجودة وثقة المراجع وأنواع الأخطاء.

## المحتوى

قائمة `lib/targets.ts` تحتوي جميع مهام التسجيل المعتمدة المستخدمة في التجربة الحالية: القبلي، المستوى الأول، المستوى الثاني، المستوى الثالث، التقويات الصوتية، الطلاقة الموقّتة، والبعدي. إجمالي أهداف التسجيل الحالية 90 هدفًا.

## ما يستطيع المختبر قياسه الآن

- أداء Azure في تحويل القراءة إلى نص.
- المطابقة اللفظية مع المرجع المعروف.
- C/D/I/S وWER والدقة اللفظية.
- تغطية كل هدف وعدد العينات الصحيحة والخاطئة.
- جودة التسجيلات.
- أخطاء النطق الموسومة بشريًا وحالات الالتباس.
- اتفاق مراجعين مستقلين.
- Azure مقابل Ground Truth البشري بعد اكتمال المراجعات.

## ما لا يجوز ادعاؤه الآن

- لا توجد بعد درجة صوتية معتمدة للفتحة/الكسرة/الضمة/السكون/الشدة.
- ثقة Azure ليست Pronunciation Score ولا Haraka Score.
- `calibration_state = not_calibrated` حتى نغلق مجموعة بيانات كافية ونختبرها على Validation set مستقل.
- المختبر لا يعطي أثرًا أكاديميًا للطالب: `academic_effect = none`.

## شروط الانتقال من جمع البيانات إلى الاعتماد

1. جمع عينات متوازنة لكل نوع هدف، وليس التسجيلات الصحيحة فقط.
2. وجود أمثلة أخطاء مقصودة مثل بَ/بِ/بُ/بْ وحركات داخل الكلمات.
3. مراجعة بشرية مستقلة، وعينات مختارة بمراجعين اثنين على الأقل.
4. عزل Development/Calibration عن Validation.
5. حساب confusion matrix وFalse Accept وFalse Reject لكل فئة نطق مستهدفة.
6. تثبيت thresholds وإصدار Calibration Version موثق.
7. فقط بعد ذلك يمكن إضافة acoustic classifier وإظهار ما أثبتته المعايرة.

## إدارة المشاركين

لا توجد أكواد افتراضية أو حسابات جاهزة. قاعدة البيانات تبدأ بلا مشاركين، ولا يمكن إنشاء كود مشاركة إلا من لوحة المشرف المحمية.
